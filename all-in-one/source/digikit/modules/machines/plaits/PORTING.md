# Porting one Plaits engine to the PLAITS machine

For an agent that ports one upstream engine (model number fixed by the plan, docs/plans/2026-10-17-plaits-all-engines.md,
"Global Constraints") from `../eurorack/plaits` (f4cfa76) and `../eurorack/stmlib` (e3bd7c9). Read AGENTS.md first.
Best templates: TERRAIN (`engines/terrain.c`, `tests/plaits/test_terrain_host.py`) for a stateless-ish engine, RINGS
(`engines/modal.c`, `test_modal_host.py`) for a strike engine, SPEECH for table-heavy ones.

Rules that never bend: no firmware bytes or `out/` in commits; never name the vendor DSP toolchain (say "selcc" and
"Selache" as the C compiler and assembler, as the findings do); never `--no-encoding-gate`; never weaken the gate or
the cross-check; no 47,872 Hz anywhere (a0 and the corrected rate are exactly 48,000); every digest change is deliberate
and says why in its commit.

## 1. Recipe

Numbers: `NAME` = the engine's file stem, `N` = its model number, `Xxx` = its C type.

1. **Port the C** (C99, float only, no libm calls beyond what `dsp_util.h` offers):
   - `src/dsp/engines/NAME.{c,h}` (`NAME_init(Xxx*)`, `NAME_render(Xxx*, const Params*, float *out, float *aux, int n)`,
     16 samples per call: `PLAITS_SUB`), shared helpers in `src/dsp/lib/` (check what exists: sine, svf, one_pole,
     resonator, wavetable_oscillator, chord_bank, string_synth_oscillator, fast_sine_oscillator, tables).
   - Tables are generated by a script next to them (`lib/gen_*.py`, `engines/gen_ws_tables.py`) from upstream's data.
     Initialised float tables are uint bit patterns (drift 2); big tables are `const` tables, not per-voice state (drift 11).
2. **State into the union** (`src/dsp/plaits.h`): `#include "engines/NAME.h"`, add `Xxx name;` to the union, add
   `#define PL_NAME(v) ((Xxx *)(void *)&(v)->engine)` and `#define PLAITS_MODEL_NAME N`. Never name a non-first member.
   If `sizeof(Xxx)` exceeds the union, `VOICE_BYTES` in `tests/support/plaits_rig.py` changes (the build test says so).
3. **Wrapper dispatch** (`src/dsp/plaits.c`), four places: `note_on` (init branch), `render_engine` (render branch),
   `plaits_ported` (enabled set), and the header comment. OUT/AUX gain rows already exist for all 24 models
   (`plaits_out_gain`, `plaits_aux_gain`; checked against voice.cc by `test_output_gains_equal_upstream_voice_cc`).
   For a strike engine take the trigger from `p->trigger & 1` (RISING_EDGE), see drift 7.
4. **Module rows**: add the .c files to `sources = [...]` in BOTH `modules/machines/plaits-48k/module.toml` and
   `plaits-96k/module.toml`; update the `summary` of `modules/machines/plaits/module.toml`. The MODEL formatter
   (`src/cf/model_fmt.s`, `tests/patchkit/test_plaits_model_names.py` NAMES) already lists all 24 names; MODEL's
   `max = 0x1800` covers 0..24 (model 24, DX7-4). A model not in `plaits_ported` renders zeros.
5. **Host build and oracle** (`tests/support/plaits_host.py`, `tests/plaits/oracle/`):
   - add `DSP / "engines" / "NAME.c"` to the source list in `build_port` (about line 215) and `"name"` to the engine-name
     tuple in `Port.__init__` (about line 80), plus `name_size: int` on `Port`;
   - `tests/plaits/oracle/port_sizes.c`: `#include "engines/NAME.h"` and `int port_name_size(void)`; its
     `PL_INDEX_CHECK` recorder is the hook for the index-range assertions (index asserts "real": the test fails if the
     recorder is not hit);
   - **oracle hook**: `tests/plaits/oracle/run_oracle.cc` builds the upstream engines against `../eurorack`: add the
     `#include "plaits/dsp/engine*/NAME_engine.h"`, a member in the struct, a `case N:` in the engine selector;
     `tests/support/plaits_oracle.py` `build()` lists the upstream .cc files to compile (add the engine's, and its
     dependencies; patch upstream text only through a fail-closed guard like `TERRAIN_GUARD`).
6. **Host tests**, `tests/plaits/test_NAME_host.py` (basename unique; copy the structure of test_terrain_host.py):
   bit-exact against the oracle over the knob corners x 4 pitches x accent values, 16- and 12-sample blocks, long
   sweeps with irregular triggers, extremes (finite and equal), index-range checks, tuning (440 Hz at note 69 within
   a cent), state size, wrapper renders it, and a **mutation table** in the report (47,872.34 in the pitch path must
   fail many tests). Run with `PLAITS_ORACLE_REQUIRED=1` so a missing oracle fails instead of skipping.
7. **Registration table** (the single point, `tests/support/plaits_vectors.py` `MODEL_TABLE`): add
   `N: ("NAME", "<image>"),` where `<image>` is the label of the hardware image whose sources first enable the model
   (h3g, ...). That alone feeds `ENABLED`, `NEW_MODELS`, `RECORDED_AT`, `vectors(N)`, the compiled-core equivalence,
   extreme, run-on, switch and model-row tests, `test_continuous_host.py` and the "unported models are silent" tests.
   Still per-model by hand (they are data about the engine): `MAX_BLOCK_INSTRUCTIONS_NEW[N]` in
   `tests/patchkit/test_plaits_module.py` (measured worst block x about 1.15, mode 1 and mode 0),
   `tests/support/plaits_streams.py` `switch_stream` sequence (put N in it), `tools/patchkit/pk_proof_plaits.py`
   `NEW_MODELS` (the emulator proof's part i; tools cannot import tests), the engine's own knob settings in
   proof part i, and a README/design line.
8. **Digests** (recipe (g), models after N stay bit-identical): record the model's first digests once, from the sources
   that enable it, host then core:
   ```
   PLAITS_RECORD_MODEL=N uv run pytest -q "tests/patchkit/test_plaits_model_digests.py::test_model_host_wrapper_unchanged[1-N]" "tests/patchkit/test_plaits_model_digests.py::test_model_host_wrapper_unchanged[0-N]"
   PLAITS_RECORD_MODEL=N uv run pytest -q --slow "tests/patchkit/test_plaits_model_digests.py::test_model_compiled_core_unchanged[1-N]" "...[0-N]"
   ```
   (ids are `[mode-N]`). The host record asserts the digests equal upstream rendered continuously
   (`reference_digests`). Core digests need `--slow` (minutes). Commit the new `tests/plaits/vectors/modelN_<image>.json`
   in its own commit. Re-recording an older model is never allowed unless the cause is a deliberate behaviour change
   (`PLAITS_RECORD_10B` shows the pattern: old digests move under a `pre_*` key and a neutral build proves what changed).
9. **Compiled-core tests** (`tests/patchkit/test_plaits_module.py`, concrete core): equivalence to the host build
   (`MAX_ERR 2e-3`, `RMS_ERR 1e-4`, 4 settings x 2 modes), extreme grid with an instruction bound (slow), run-on, model switch to
   and from VA (`assert_model_switch`), model row, C stack bytes. They parametrize over the table; add an engine-specific
   test only for what is new (a worst-case path like TERRAIN's jumps).
10. **CPU** (recipe (e), safety rule): `PORTING.md` section 3 gives the commands: fuzz first (`--fuzz`, minutes, finds
    the worst knobs and sequence on the isolated routine), then one `--confirm` emulator run. Record the 1-track high-bound load and
    the extrapolated 2-track load in finding 06 as a new [D] section. Over 85 % at 1 track: the engine ships silent
    (remove it from `plaits_ported`, `MODEL_TABLE` stays out) and is listed "ported, disabled: over budget".
11. **Image and owner checks** (the gate runs by default):
    ```
    uv run python -m tools.patchkit.patchkit patch --firmware firmware/Digitakt_II_OS1.17.syx \
        --modules ui/boot-splash,machines/plaits-48k -o out/patch/plaits-NNmodels-names-splash-48k-1.17.syx
    elektron-firmware-tool -i X.syx                                  # checksums : ok
    uv run python -m tools.sharc_dev.sharc_bootcheck --syx X.syx --stock firmware/Digitakt_II_OS1.17.syx   # 0 errors
    uv run python -m tools.patchkit.pk_encoding_gate X.syx X.plan.json                                     # 0 violations
    ```
    and sections 2, 4, 5 and 8 byte-equal to stock (`uv run python -m tools.firmware.extract`, compare). Refresh the
    committed objects with `mise run patch:build -- modules/machines/plaits-48k` (and `-96k`) BEFORE `patchkit patch`: it refuses (exit 1, nothing written) when a committed object of the selected modules or their `requires` is stale (`--allow-stale-objects` goes on and names the image `*.stale.syx`); `--check` finds stale ones.
    Report section 7's size against the 0xFFFFF boot-stream cap.
12. **HARDWARE-TEST.md**: append the section below, update the title line, the image table (sha256, build command,
    commit) and the "track limits" bullet in "Known, not faults".
    ```
    ## H3x: model N, NAME (only after H3<prev> passed)

    H3x (`out/patch/<image>.syx`, `<sha8>…`) is H3<prev> plus model N, NAME. Values from .. to 23 still play silence.

    1. **Boot and a new project.** Flash, power on (splash, boot), create a new project, FUNC+SRC, 7 x DOWN, YES on
       track 1; make sure track 2 has a sample and plays.
    2. **Model N.** MODEL (B) to N: the header reads `Model=NAME`. Trig note 60: what it should sound like;
       HARMONICS (C), TIMBRE (E), MORPH (F), MIX (G): what each does (from upstream's docs).
    3. **Velocity / trigger** (strike engines only): velocity 127 against 30; fast retriggers: no runaway, no crackle.
    4. **Level** against VA at default knobs: within a few dB (the output stage is Plaits' own).
    5. **Track rule:** never more than K tracks triggered as PLAITS since boot (measured X % at the high bound).
    6. Save with MODEL N, reboot, load: MODEL is back and NAME plays.
    - **H3x stalls or is silent** while H3<prev> passed: recover (hold FUNC at power-on, TRIG 4, send the stock
      `firmware/Digitakt_II_OS1.17.syx` with Transfer's legacy mode), go back to H3<prev> and report which step failed.
    ```
13. **Report** to `.superpowers/sdd/<plan>/task-N-report.md` (what was ported, tables bit-checked, mutations caught,
    CPU, section 7, image sha, tests run and NOT run) and commit with explicit paths.

## 2. Drift catalogue

Each entry: symptom, detection, standard fix. "Host" = host build vs upstream oracle; "core" = compiled object on the
concrete core vs host.

1. **Selache encoding gate refusals** (finding 20). Symptom: `patchkit patch` deletes the image; the gate lists a word
   shape not in stock. Seen: `Fn = FLOAT Rm` with n != m (2a_short), integer multiply by 6, `RTS` non-delayed, return
   through `JUMP (M13, I13)`. Detect: the gate on the built image (step 11; also `pk_encoding_gate` on a module-only
   build). Fix: change the C so selcc emits a stock shape: int-to-float through `itof_nonneg` (exact for 0 <= i < 2^23),
   multiplies by non-powers of two as shifts and adds (`(i << 2) + (i << 1)`), integer `/` and `%` as shifts, masks and
   a conditional subtract. Never list a shape in `encoding_proven.toml` without an owner-unit image that executed it.
   Also: indirect jumps are written outside `.NOCOMPRESS` (Type 9a is mis-encoded); no PM data transfers.
2. **Negative float initialisers** (finding 20). Symptom: a table entry is garbage (-1.0f reads as -4.0) only on the
   core; the half-band and the FM ratio table hit it. Detect: core equivalence fails, and the tests that compare the
   object's table bytes with host bits (`tables equal host bits`); neither the gate nor the cross-check can see data.
   Fix: store IEEE bit patterns in `const unsigned int` arrays (generated by the `gen_*.py` scripts) and read them
   through `PL_F(table)[i]` (`dsp_util.h`). Negative integers in tables are fine. Applies to every float table
   with a negative entry, and to small ones too (`plaits_out_gain`).
3. **Union layout** (finding 20, rulings A). Symptom: an engine reads another engine's bytes; works on the host, wrong
   on the core. selcc puts each union member after the previous one. Detect: `pk_build`'s union lint (`pk_cunion`) refuses
   `.member` of a non-first member at build time (it also refuses what it cannot parse), and the core tests. Fix: only
   `PL_*` casts, `(Xxx *)(void *)&v->engine`; no attributes on unions; helpers that need another view use
   a pointer-cast form (`itof_nonneg`, `hb_up2`).
4. **Float rounding and compiled tolerance.** Symptom: bit-exact host, core off by 1e-7..1e-5. Cause: selcc has no FMA
   contraction control, division is RECIPS + Newton, constants in code are rounded floats. Detect: compiled equivalence
   with `MAX_ERR 2e-3` / `RMS_ERR 1e-4` (the established tolerance; measured errors are 1e-6..1e-5, 0 for some). Fix: none
   to the sound (do not loosen the tolerance; if a model needs more, find the cause). Write tan<FAST>-style constants as
   their rounded float values, compute `SemitonesToRatio`-style tables in float32 in the generator. The host build
   must stay bit-exact with upstream (`==` on uint32 words), core digests are pinned instead (they cannot be oracle-checked).
5. **Out-of-range table reads** (TERRAIN ruling). Symptom: host and oracle differ, or the core returns NaN/garbage after
   a parameter jump; upstream reads outside its table (undefined behaviour). Detect: index-range assertions
   (`PL_INDEX_CHECK` recorder in port_sizes.c), fuzzed jump sequences, and the slow compiled jump test. Fix: ruling of
   Task 10b: do not bake another build's memory. Wrap (sine and wavetable phase are periodic) or clamp so every read is
   inside the table, deviate from upstream only where it is undefined behaviour, and make the oracle apply the same
   guard to upstream's own text, only at those points, failing closed (`TERRAIN_GUARD`). Document the deviation in the
   .c header, finding 06 and the README; do not claim "as Plaits does".
6. **NaN / Inf.** Symptom: one engine overshoot or a UB read makes the DC blocker or the limiter latch NaN; the track is
   silent until a model change. Detect: finite-output assertions at extremes, `test_output_stage_takes_nan_and_inf_as_zero`.
   Fix: `plaits_post` maps a non-finite sample to 0 before the limiter and the clip; keep IIR state fed only finite
   values (guard the engine's own recursive paths); the oracle's stand-in and the Python tail do the same.
7. **Init, run-on and the trigger convention.** Plaits is not re-initialised per note: `note_on` (plaits.c) inits only at
   the voice's first note-on and at a model change (after a model change the engine starts from Init + LoadUserData(NULL)
   + Reset). A per-note init replays power-up state and clicks (WAVETABLE, CHORD). Detect: `test_continuous_host.py`
   (retrigger and switch streams against the oracle, bit-exact, 48k and 96k), click/sweep tests. Fix: the engine's state
   lives in the union and `NAME_init` = Init + Reset; never reset in render. **Strike engines** (STRING, RINGS, KICK,
   SNARE, HIHAT) get Plaits' trigger from the DT2 note-on, never `TRIGGER_UNPATCHED`: RISING_EDGE | HIGH in the note-on's
   first sub-block, HIGH after until the next note-on, no release; only RISING_EDGE matters. The sustain
   (UNPATCHED) branch is unreachable: do not port it, say so. Test: every note-on strikes, HIGH or LOW after the edge is
   identical, bounded energy under strikes every block for 20 s and 1/32 notes at 300 BPM, accent RMS ratio.
8. **Accent.** The note-on's velocity word / 0x7f00 is latched as `accent` at every note-on (default velocity 100 gives
   0.787, Plaits' LEVEL-unpatched 0.8). Only SPEECH, RINGS, STRING, KICK, SNARE, HIHAT (and DX7) read it upstream.
   Detect: `test_velocity_changes_nothing_for_models_without_accent` (velocity 0/127/mixed must not change models
   that do not read it) and bit-exactness at mixed velocities for those that do. Fix: engines read `p->accent` only
   where upstream does; add the model to the oracle streams with velocities.
9. **Output stage: gains and limiter.** Plaits applies per-model OUT/AUX gains and, for a negative gain, stmlib's
   Limiter, then Clip16 (here a clamp to [-1, 1]); then the wrapper mixes, DC-blocks and applies `plaits_gain`
   (0.601/0.8). Symptom of forgetting: a model 12 dB loud (SPEECH 2.4 raw peak). Mapping: model n = upstream engine
   (n + 8) mod 24. Detect: `test_output_gains_equal_upstream_voice_cc`, host digests equal `reference_digests` (upstream
   with its output stage), neutral build (`PL_OUTPUT_STAGE_NEUTRAL`) reproduces the pre-stage digests of models 0..7.
   Fix: nothing per engine beyond the table row; do not touch `post`. Limiter state: OUT peak reset at every engine init
   (0.5), AUX peak at the voice's first note-on only.
10. **47,872 to 48 kHz.** Upstream bakes `kCorrectedSampleRate = 47872.34` into pitch tables and `a0`. The port runs
    from exactly 48,000: `a0 = (440/8)/48000`. Symptom: 0.3 % (about 5 cents) flat/sharp; Detect: the oracle is built with the
    48 kHz constants, so any leftover 47,872 fails dozens of tests; also the 440 Hz-at-note-69 check. Fix: regenerate
    every table that bakes in the rate (generators in `lib/gen_*.py`); grep `47872` before finishing; the mutation
    run (47872.34 in the pitch path) must fail many tests.
11. **Large tables, tables rather than arena** (ruling B). Upstream's 16 KB arena per voice would be about 265 KB for 16
    voices in L2 (922,756 B). Fix: if the data depends only on a bank or a parameter (SPEECH word banks decoded once by
    the generator, TERRAIN waves), make it a generated `const` table shared by all voices and keep the union small; only
    true per-voice buffers (delay lines, DUST diffuser, STRING) go in the union. Report state and table bytes and the
    section-7 size (cap 0xFFFFF, boot stream). An arena that must be zeroed is a Reset cost at model change: measure it
    in the CPU run.
12. **CPU safety rule.** One track at the high bound over 85 % of 666,667 cycles ships silent ("ported, disabled: over
    budget"); the track limit is recomputed from the heaviest enabled model (now 1 track). Detect: `pk_plaits_cpu` (section 3) at
    the worst knobs, plus the compiled extreme grid bound. Include the model-change block (init) and slow paths
    (jumps, cold word loads) in the worst block, not just the steady state. Report 2-track figures as extrapolated
    unless measured.
13. **Shared-union side effects.** `ModalEngine::harmonics_lp_` is re-zeroed at an engine change (Reset keeps it
    upstream); first note after a model change can tick once; no re-init when a track leaves PLAITS and returns. Document,
    do not fix; test digests prove the documented behaviour.
14. **Test-only code paths.** `PL_OUTPUT_STAGE_NEUTRAL` is the only `#ifdef` allowed in plaits.c; do not add more
    shipping branches for tests (the 10b review flagged it).
15. **Oracle text patches must fail closed** (`TERRAIN_GUARD`): a patch that no longer matches upstream's text must raise,
    not silently build an unpatched oracle.
16. **A model switched away and back** resumes nothing: its state is gone (the union). The tests (switch streams)
    encode that; do not "fix" it in one engine.
17. **Velocity timing:** the shim reads the velocity halfword with the note-on frame (finding 06 [D]); proof of
    varying velocity is on hardware only (HARDWARE-TEST step 3).

18. **sqrt, rsqrt and divide are not correctly rounded on the SHARC.** Upstream's `Sqrt` is the hardware vsqrt and `/` is
    correctly rounded; the core has no sqrt and divides by RECIPS + Newton. Symptom: bit-exactness of that term is
    impossible on the core. Fix: replace it with a division-free iteration (NOISE `pl_rsqrt`, SNARE `pl_sqrt`), patch the
    same function into the oracle's copy of upstream's text (fail-closed), then bound it, test the bound over a dense
    sweep (assert the measured bound plus a small margin), and document the figure (never "exact").

19. **Heavy engine, slow confirm.** `--fuzz --confirm` with the default windows (0.5 s and 2.5 s) of an engine near 100,000
    instructions per block (PHASE-DIST) runs past the 3600 s `--max-seconds` and is stopped without a figure. Fix: run the
    fuzz, put its knobs in `WORST`, then confirm with `--image IMAGE --model N --knobs worst --windows 100,500` (about 50
    minutes with the machine otherwise idle). An emulator proof or a second emulator started during a confirm slows both:
    run them one after the other.

20. **Proof MODEL knob stops short.** `pk_proof_plaits.set_model` with single slow detents dropped turns and stopped at 0x1000
    (model 16) within its 120 turns for model 17 (10b saw 0x1200 under load for 21): part i then reports the knob check
    failed and plays silence. Fix: single detents (they cannot overshoot) with 200 turns; a fast burst only while 8 or more
    detents away and only until the first overshoot (tests/patchkit/test_plaits_proof_set_model.py: converges from any start
    to any model, and models up to 7 from 0 never burst). A knob that stops short is never a pass: the check compares the slot with n << 8.

21. **Confirm run starved by another emulator.** With another lane's CPU confirm running, even `--windows 100,500` of a 60 % engine
    (VCF-VA) passed 3600 s twice without a figure. Fix: `--windows 50,250 --max-seconds 5400` (finished); the loaded machine is the
    cause, not the engine. Also: `sharcdb build` of a patched image needs `--blocks 56,69,76,78,80,88,91,93,103,104,107` (no known list).

22. **A float tested as a condition.** `if (x)` with a float `x` compiles to a compare shape (`2a_short:18ca000`) that is in neither stock
    code nor `encoding_proven.toml`: the gate deleted the SQUARE image (3 sites, `if (discontinuity)`). Fix: write `x != 0.0f` (CHORD
    already did). Also from SQUARE: stmlib's `Random` is one global upstream, here one state per voice seeded 0x21 (the oracle reseeds
    at each engine selection), so two SQUARE tracks in random-arpeggio mode play the same sequence; and an engine that upstream runs
    in two modes (SQUARE: clocked or not) ports only the mode the DT2 trigger convention makes reachable, said in the .c header.

23. **A big per-voice buffer makes the model-init block the worst block.** STRING MACHINE's ensemble keeps a 1024-float circular delay
    buffer per voice (upstream: arena memory, cleared by Reset): the union grows from 372 to 4,304 bytes, `PlaitsVoice` from 920 to 4,852
    (`VOICE_BYTES` in tools/patchkit/plaits_rig.py; the rig's zeroing and the voice base depend on it; 16 voices 77,632 bytes), and the
    clear at a model change is a 1,024-iteration loop (about 17 % of the fuzz's worst block, the one with the note-on that selects the model).
    Fix: none to the sound; keep the buffer per voice with upstream's length and mask semantics, report the bytes and the section-7 size,
    and bound the model-change block in the extreme grid (it is in `MAX_BLOCK_INSTRUCTIONS_NEW`). The FxEngine context (accumulator
    sequences with a scale of 0.0f between reads) is written out as plain sums: equal for finite input.

24. **16-bit delay memory, the rig's tail block and the oracle's Clip16** (DUST). (a) Upstream's FxEngine<8192, FORMAT_12_BIT> stores uint16: selcc's
    16-bit loads and stores are not usable (the assembler ignores the halfword modifier on indirect accesses), so two samples are packed in one
    32-bit word (4,096 words = 16,384 bytes per voice; `DUST_READ`/`DUST_WRITE` in engines/dust.c; the signed value is mapped through a top-bit flip
    to use `itof_nonneg`; the compress saturates in the float domain and truncates toward zero as upstream's cast). `PlaitsVoice` goes from 4,852 to
    17,116 bytes (`VOICE_BYTES`), 16 voices 273,856 bytes; as a C static the voices were zeros in the boot stream (section 7 929,884 of 1,048,575): see drift 25.
    Clear the buffer through a pointer (`*b++ = 0`): the indexed store compiled to 14 instructions per word (143k to 114k instructions in the model-change block).
    (b) The rig loads the module code at `PL_BASE` and a tail block at a fixed `TAIL_BASE`: code over 90,112 words silently overlapped the tail and
    HIHAT (the first model run) jumped into garbage (`unsupported multifunction ... pc 0xba7fff`), while the new model's own tests passed. `TAIL_BASE` is now
    0xBAC000 and `PlaitsRig.__init__` asserts the code stays below it (fail closed); a new engine that pushes the code past 0xBAC000 words must move it again (RETURN_SW is 0xBAF100).
    (c) The oracle cannot include stmlib's `Clip16` on an ARM host (an `ssat` asm unless `TEST`): `dust_override` supplies an include-first copy of stmlib/dsp/dsp.h
    with only Clip16's portable branch (fail-closed on the text) next to the patched particle.h (the two `Sqrt`s, drift 18).

25. **Zero statics are loaded data: per-voice memory is `.PKBSS`.** selcc emits a zero-initialised static (`static T a[N];`, also `= {0}`) as loaded
    data, so its zeros are copied into the DSP boot stream (the cap is 0xFFFFF bytes): `static PlaitsVoice plaits_voices[16]` put 273,856 bytes of zeros
    in section 7 (STRING MACHINE's 77 KB already; DUST's 16 KB per voice took it to 929,884). Fix (DUST fix round 1): the whole voice array is
    `.PKBSS plaits_voice_mem., 273856;` in plaits_entry.s (reserved, not loaded; section 7 929,884 -> 656,244), declared `extern PlaitsVoice plaits_voice_mem[16]`
    in plaits.c under `__SELACHE__` (a plain static on the host) with a compile-time check that 16 x sizeof(PlaitsVoice) is the reserved size (and the rig
    asserts it). Reserved memory is NOT zero at load: `plaits_track` zeroes a voice's non-engine fields at its first block (`plaits_voice_ready[]`), and every engine
    state is initialised by `note_on` (armed 0 or a model change) before it is read, so an engine's init must set every field it later reads (the
    rig's `clear_voice` fills the voice with 0x5A5A5A5A and clears the flag, so the digests and the fuzz prove it). Changing `PlaitsVoice` changes `VOICE_BYTES`,
    the `.PKBSS` size and the compile-time check together. New per-voice memory goes inside the union as before; never add a big zero static.
    `pk_build` refuses a module whose loaded data (not `.PKBSS`, not `.PKDATA`) has a zero run over 4 KB (`check_zero_runs`, tests/patchkit/test_pk_zero_runs.py).

26. **Upstream divides by an engine state that is zero at start** (STRING). The f0 history of `StringEngine` is zeros after Reset, so the first strike of
    an engine copies 0.0f into the third string's f0, and `String::Process` computes `1.0f / f0` (infinity upstream, then `CONSTRAIN`ed to 1020). On the
    core a division is RECIPS + Newton and its result for 0 is not a defined quantity (NaN or garbage would reach the delay line). Symptom: nothing on the host
    (IEEE infinity), a latched-NaN voice on the core. Detect: ask of every upstream `1.0f / x` and `x / y` whether `x` can be 0 on the first block after Init
    (the oracle reproduces it at once: every first strike of the test streams is such a case). Fix: skip the division for `f0 <= 0.0f` and take the value the
    upstream result is constrained to (a documented, value-identical guard, in the .c header); the host test stays bit-exact. A float table that a new
    engine needs and the shared tables lack is added to `lib/gen_lib_tables.py` (STRING: `lut_svf_shift`, 257 entries, last in the list so the earlier tables'
    indices in `port_sizes.c` and `test_compiled_lib_tables_equal_host_bits` stay put).

27. **An integer constant inside a float constant expression** (STRING). `CONSTRAIN(delay, 4.0f, kDelayLineSize - 4.0f)` with `kDelayLineSize` an integer macro made selcc
    convert the integer at run time: the gate deleted the image with two `2a_short:18ca000` instructions (a float compare shape, the same one as drift 22) in
    the function that held the clamp. Fix: write the folded float literal (`1020.0f`, with a comment giving the expression). Detect: the gate on the built image
    (step 11); find the function with the plan's symbols (the nearest label below the flagged pc). Check every `INT_MACRO +- float` and `INT * float` constant in a new engine.

28. **A stateful quantiser behind a displayed name: made memoryless** (DX7; shipped as a deliberate deviation, owner decision 2026-10-23).
    Upstream's patch picker is a `HysteresisQuantizer2` with hysteresis 0.005: the patch that plays at a HARMONICS word on a step
    boundary depends on the direction the knob came from (word 0x2300, UI 35, is such a boundary), so a display that sees only the
    knob value could name the wrong patch. The DX7 models therefore use the same quantiser with the hysteresis 0 (the nominal
    thresholds): patch = a fixed function of the HARMONICS word. One generated table (`lib/gen_dx_tables.py`, `patch_of_word`: the
    float32 chain of upstream's `Process`, `pl_dx7_patch_word` / `pl_dx7_patch_thr` in `lib/dx7_banks.c`, the same words in
    `src/cf/dx7_names.s`) serves the DSP (`six_op_patch_index`, a 5-step search of float compares against `unit(boundary word)`) and the
    ColdFire names, so name and patch cannot disagree. The oracle applies the same (`support/plaits_oracle.py` `memoryless_six_op`
    builds upstream's six_op_engine.cc with `Init(32, 0.0f, false)`); tests: every word 0..0x7f00 equals upstream's quantiser,
    boundaries from both directions render bit for bit, the generated files are current. Other models are untouched (bit-identical).
    Detect a regression: `test_the_patch_of_every_harmonics_word_is_upstreams_quantiser_without_hysteresis`. The knob-turn header
    shows the name (finding 02, "PLAITS DX7 patch names"); other screens keep the number.

29. **Gate from the note-off: the DX7 exception** (DX7, like SWARM's continuous mode for the trigger). The convention (drift 7) is note-on
    only, HIGH until the next note-on. The DX7 models read the Digitakt's note-off: core/dsp-inline `_di_released(v)` reads the DSP's
    per-voice release flag (byte `0x24f0ec + v`, anchor `dsp.inline.release_latch` = the trigger latch's literal + 0x40: FUN_1c6056
    stores 1 at a note-off, the trigger path stores 0), the shim copies it to `PlaitsFrame.released`, and plaits.c gives the DX7
    models RISING_EDGE | HIGH in a note-on's first sub-block, HIGH while the flag is 0 and LOW from the note-off to the next note-on.
    Tests: the oracle is driven with the same gate (`reference` takes `released`, `gate_stream`); the compiled core reads the flag
    through the rig (`PlaitsRig.release`); the emulator proof part m peeks the byte and the frame word at a TRIG hold and release.
    The port file devices/ports/dt2-1.17.toml needs the anchor added by hand when the ColdFire database of 1.17 (out/cfdb) is not
    available to `port_resolve` (the same entry, one line different from the trigger latch's: addr = literal + 0x40).

30. **A new patch is a blank block** (DX7). Upstream's `Voice::Render` does the patch setup (envelope constants, ratios) and returns
    without rendering, "to prevent a CPU overrun": the first sub-block that renders a voice after a patch load is silent, and a note of
    one block (two sub-blocks) is nearly silent. Ported as it is; the model-row test renders three blocks of a DX7 model. The
    four-bank size is 16 KB of tables (`lib/dx7_banks.c`, four packed bytes per word) and the first-note block is the CPU worst block.

31. **The rig's tail block moved again** (as drift 24b): the module code passed 0xBAC000 with the six-op engine and its tables
    (`TAIL_BASE` is 0xBAE000, RETURN_SW is still 0xBAF100: the next engine that grows the code past 0xBAE000 moves both).

## 3. CPU command

**Fuzz first.** The emulator takes up to an hour per knob setting, so worst knobs picked by hand can be missed (TERRAIN's
post-jump path was). `--fuzz` searches on the compiled routine alone, the rig of the compiled-core tests
(`tools/patchkit/plaits_rig.py`, no image, no emulator), counting instructions per block over random sequences: knobs
across the range and at the extremes, notes with big jumps, velocity, note-ons at random spacing (fast retriggers),
switches into the model by a note-on or by turning MODEL first, with plaits.c's run-on and strike conventions. It is
CPython-bound: about 100 blocks per minute per process (`--jobs 3` for three times that), so give the model 3 to 10
minutes. It prints the worst block against the recorded worst (`RECORDED_WORST` in `pk_plaits_fuzz.py`: add the new
model's figure there) and writes `out/runs/plaits-cpu/fuzz/mN-seedS-jJ-nK-<UTC time>.json` (the worst sequence; never overwritten). With `--budget-seconds` alone the search is deadline-bound, so the same seed is NOT reproducible across machine loads (NOISE: 64,832 idle, 63,391 under load); give `--sequences K` when you need a reproducible search, and keep the file of the run that sets `RECORDED_WORST`.

```
uv run python -m tools.patchkit.pk_plaits_cpu --fuzz --model N [--seed S] [--budget-seconds 180] [--jobs 3] [--sequences K]
```

The cycle model subtracts the totals of two runs (short and long window), which assumes boot and the panel steps cost the
same in both. When they do not (NOISE at MORPH 0x173c: negative cycles, cause not established, probably the panel steps
settling differently for that knob value) the tool now fails: `cycle_model_invalid`, exit code 1, never a pass. OPEN: the cause.
Rerun, or put a knob value in `WORST` that measures (MORPH 0x7f00 did).

Put the knobs it reports in `WORST` and raise the model's `MAX_BLOCK_INSTRUCTIONS_NEW` if it found more than the grid did.

**Then one `--confirm` run** (the same command plus `--confirm --image out/patch/IMAGE.syx`): the worst block's static knobs
and note (carried by TUNE, the emulator plays note 60) go through the emulator below and the real share of the DSP
budget is printed and stored in the fuzz JSON. Velocity and MIX are not carried.

One engine at its worst knobs, on a built image (slow: the cycle model interprets; about 10 minutes per second of audio,
default windows 0.5 s and 2.5 s, so run in the background and budget about 45 minutes; `--max-seconds` bounds it):

```
export RUSTUP_TOOLCHAIN=1.98.1-aarch64-apple-darwin SHARC_GEN_DIR=out/native/shared-core/gen DIGI_EMU_READY_DIR_DT2=out/ready-pk-dt2-117
uv run python -m tools.sharc_dev.sharcdb build out/sections/<image>/section_7_BLOB.bin   # once per image: out/sharcdb/<image>.sqlite
uv run python -m tools.patchkit.pk_plaits_cpu --image out/patch/IMAGE.syx --model N [--tracks K] [--knobs worst|HARM=0x7f00,TIMB=0x4000,MORPH=..,TUNE=..]
uv run python -m tools.patchkit.pk_plaits_cpu --image out/patch/IMAGE.syx --model N --no-cycles --windows 100,500   # quick counters only
```

It prints the busy instructions per block, the cycles per block and the % of the block (low / nominal / high), and
whether the high bound is within 85 %; the JSON is `out/runs/plaits-cpu/mN-tK.json`. It always stops its emulator. Add the
model's worst knobs to `WORST` in the tool once the fuzz or the compiled extreme grid names them. Set the two env lines to the
lane's own paths. Run models in parallel only when the machine is free (each run is one emulator).

## 4. Pitfalls on cost

- Run only the tests you touched: `uv run pytest -q tests/plaits/test_NAME_host.py tests/patchkit/test_plaits_cpu.py`,
  and `-k` to your model in the compiled tests (the model number is in the test id). Never run `tests/patchkit/test_plaits_module.py`
  whole with `--slow` (over an hour); never re-run old full proofs for a baseline already in finding 06.
- One slow run at the end of the task: the core digests of the new model and the extreme grid of the new model; then stop.
  Do not run slow sweeps for other models unless a shared file (plaits.c, plaits_vectors.py, dsp_util.h) changed
  behaviour; if it did, that is a behaviour change with its own deliberate digest commit.
- Record digests once, at the end, from the final sources; a re-record after a late fix means another slow run.
- Write the tests and the mutation checks first; a wrong port found by a 70-minute run is a 70-minute loss.
- Emulator runs (CPU tool, `pk_proof_plaits`): bound them (`--max-seconds`, `PLAITS_PROOF_MODELS=N` for part i), start
  at most what you need, and stop only what you started (by PID or run directory; never `pkill`).
- Missing oracle: tests skip. Set `PLAITS_ORACLE_REQUIRED=1`; do not report green on skipped tests.
- Lint and types before committing: `uv run pytest -q tests/devtools/test_lint.py tests/devtools/test_types.py`; new
  Python files join `TYPED` in test_types.py (lint covers `tests` and `tools` already).
- Commit with explicit paths, in logical commits (code, digests, docs); never `out/`, firmware or an image.

## 5. SIMD-friendly from the start (owner, 2026-10-20)

Every new engine is ported so that a SIMD kernel can replace its hot loop without restructuring. The RINGS resonator
went from 111 instructions per filter-sample in compiled C to 16 for four filters (`lib/resonator_svf4_sm.s`, H-opt2,
verified on the unit with three RINGS tracks); `OPTIMIZING.md` holds the rules and lessons. At port time:

1. **Keep the C as the reference.** The host oracle and the compiled-equivalence tests run the plain C; a kernel must
   match it bit for bit (same operations, same order per lane). Never write C whose order a kernel couldn't reproduce
   (no `-ffp-contract`, no reassociation).
2. **Find the hot loop on day one.** After the port passes, run `pk_dsp_waste --model N` and record in the report which
   function and loop hold most of the cycles, and their instruction mix.
3. **Lay out state for pairs.** Where upstream runs N independent instances of the same thing (oscillators, filters,
   modes, voices of a chord, partials, grains, the main and aux paths), keep their state in arrays of structs of
   *pairs* or structs of arrays with an even count, contiguous and 8-byte aligned, so PEx/PEy can take one each. Pad an
   odd count with a dummy lane whose result is discarded, if that keeps the arithmetic identical.
4. **Process blocks, not samples, in the hot loop:** a loop over the block with the per-instance state loaded once
   before and stored once after (register-resident), no calls inside, and loop-invariant coefficients hoisted. Write
   the C this way where upstream allows it without changing results.
5. **Kernel threshold.** If the hot loop holds more than about 40 % of the engine's worst block, say so in the report:
   the coordinator schedules a kernel step (hand-written SIMD, on the more capable model) for it, using the RINGS kernel
   as the template.
6. **Hardware rules for any assembly** (both learned on the unit, see `OPTIMIZING.md` and finding 06's history):
   - Never store a DAG register through its own DAG (`DM(I7, M7) = M4` and the like). The PRM forbids it (pp. 14-12,
     14-15, 16-7, 16-10), the emulator executes it anyway, and it crashed the DSP on the unit. Save DAG registers through
     a data register. `pk_encoding_gate` refuses it.
     The PRM's text (Types 3a, 15a) forbids the load direction too (`L4 = DM(1, I7)`); the kernels restore DAG
     registers that way on purpose, as stock does thousands of times and as the RINGS and drum kernels do on the unit.
   - No data transfers while SIMD mode is on, until a probe proves them on the unit: do SISD loads and stores and fill
     the S registers with register moves (the `_sm` kernel pattern). `pk_encoding_gate` refuses them.
   - Set every mode or DAG register the kernel depends on (M, L, B, MODE1 bits) and restore it on every exit; the
     full-state test (`tests/plaits/test_resonator_kernel.py`) is the template.
   - The SHARC+ Core Programming Reference is extracted at `out/refs/sc58x-2158x-prm/`: check the operand restrictions
     of every instruction type you use, not only that a stock precedent exists.
